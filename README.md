# Data & Cloud Architecture Reading List

A highly selective collection of insightful and impactful articles about:

- Cloud architecture
- Azure and Azure Databricks
- Data platforms and governance
- Unity Catalog and ABAC
- Distributed systems
- Platform engineering
- Interoperability and open standards
- AI and LLM governance

The selection prioritizes powerful ideas, reusable mental models, practical
production lessons, and second-order architectural consequences over technical
depth alone.

## Repository layout

- `articles.yaml` — **starting point**. Machine-readable list of articles to
  archive as PDFs.
- `src/archive-articles.mjs` — Node script that reads `articles.yaml` and
  produces one PDF per article under `pdfs/<category>/<id>.pdf`.
- `pdfs/` — generated PDF archive, organized by category.
- `articles/` — human-written reviews and notes, one Markdown file per
  category (e.g. `cloud-architecture.md`, `data-governance.md`).
- `templates/article-review.md` — template used when writing a new review.
- `backlog.md` — articles queued for reading and evaluation.
- `archive-report.json` — run report generated by the archive script
  (git-ignored).

## Adding a new article

1. Add an entry to `articles.yaml`:

   ```yaml
   - id: my-article-slug          # required, used as the PDF filename
     title: "My Article Title"    # required
     url: "https://example.com/…" # required; direct .pdf URLs are supported
     category: cloud-architecture # required, becomes the output subfolder
     rating: 9                    # optional
   ```

2. (Optional) Write a review in `articles/<category>.md` using
   `templates/article-review.md`.
3. Run the archiver (see below).

## Archiving articles as PDFs

Prerequisites: Node.js 20+.

```bash
npm install
npx playwright install chromium
npm run archive
```

The script:

- Skips any article whose PDF already exists at
  `pdfs/<category>/<id>.pdf` (delete the file to force a re-archive).
- Uses Playwright (headless Chromium) to render HTML pages to PDF.
- Downloads URLs ending in `.pdf` directly via `fetch`, validating the
  `application/pdf` content-type and the `%PDF-` signature.
- Writes a summary to `archive-report.json` with one entry per article and a
  `status` of `success`, `skipped`, `blocked` (HTTP 401/403), or `failed`.
